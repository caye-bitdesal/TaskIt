Task Manager

Kanban de tareas y CRUDL de releases en KMP (Ktor + SQLDelight en el server; Android, Web y Desktop tontos vía REST). Sin iOS. Columnas fijas: To-Do, Selected, In Progress, Ready, Done.

Overview

TaskIt es un gestor pequeño: el server es la fuente de verdad (SQLite con SQLDelight, Metro, REST). Los clientes Compose Multiplatform solo presentan lo que devuelve la API.

Dominio

  • Release: id, name (obligatorio), notes (opcional).
  • Task: id, title (obligatorio), description (opcional), status, releaseId (opcional). Sin personas ni avatares.
  • Status: TODO | SELECTED | IN_PROGRESS | READY | DONE.

Reglas del board

  • To-Do: tareas sin release. El filtro All / una release no las oculta.
  • Selected: tienen release y status == SELECTED. Filtro All = todas esas; una release = solo esa.
  • In Progress / Ready / Done: ese status + filtro de release (All = cualquiera con release).
  • Crear tarea → releaseId null → To-Do. Asignar release en el editor → status = SELECTED.
  • No se puede mover a In Progress / Ready / Done sin release.
  • Quitar la release en el editor → vuelve a To-Do (status = TODO, releaseId = null).
  • Borrar una release que aún tiene tickets → 409.

UI (después del server)

  • Sin sidebar. Una pantalla a la vez. Sin diálogos excepto TaskActionDialog.
  • Top bar: título, botón Releases, Nueva release (solo en la lista de releases), toggle claro/oscuro (sigue el sistema + override).
  • Board: 5 columnas; en ancho estrecho scroll horizontal. FAB Nueva tarea.
  • Card: título + nombre de la release. Tap corto → diálogo Mover / Editar / Borrar. Long-press: nada. Borrar inmediato.
  • Editores a pantalla llena (tarea y release).
  • Loading centrado, error + Retry, columnas vacías "No tasks", lista vacía "No releases".

Plataformas: :server, :app:androidApp, :app:webApp, :app:desktopApp compartiendo :app:shared. No implementar iOS.

Orden de implementación: primero todo el server (modelos, SQLDelight, Metro, endpoints, tests). Luego capa HTTP del cliente. Luego UI por feature (shell → board → editor de tarea → releases).

Persistence

SQLDelight + SQLite solo en :server. El cliente no cachea (ni Room ni SQLDelight).

Tablas:

  • Release(id TEXT PK, name TEXT NOT NULL, notes TEXT)
  • Task(id TEXT PK, title TEXT NOT NULL, description TEXT, status TEXT NOT NULL, releaseId TEXT REFERENCES Release(id), createdAt TEXT, updatedAt TEXT)

Fichero SQLite en el working dir del server (p. ej. taskit.db). Metro: ServerGraph provee SqlDriver / DB y repos @SingleIn(ServerScope).

Tema del cliente: override light/dark en memoria de sesión; no persistir.
